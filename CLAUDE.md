# JobMatch – project context for Claude

Job-matching web app for **all job seekers in the Netherlands** (Dutch first, English UI as secondary locale).
The goal is to aggregate the major Dutch job boards and employer ATSs via connectors (APIs added over time).
Users upload a CV, complete a short evidence-based onboarding and get **explainable** matches.
Admins manage job-source connectors and the (versioned) matching model.

The system is treated as **high-risk under the EU AI Act** (employment). Compliance rules below are
not optional.

## Stack

- Next.js 16 (App Router, Turbopack, `src/proxy.ts` instead of middleware), TypeScript strict
  (+ `noUncheckedIndexedAccess`), Tailwind v4, shadcn-style UI primitives in `src/components/ui`
  (hand-written, built on the unified `radix-ui` package – the shadcn registry is not reachable
  from the dev container).
- next-intl v4: locales `nl` (default) and `en`, `localePrefix: "as-needed"` → `/…` is Dutch,
  `/en/…` is English. Messages in `messages/{nl,en}.json` (typed via `src/global.d.ts`; `nl.json`
  is the source of truth for keys – keep `en.json` in sync, a Vitest test checks this).
- Supabase: Postgres + pgvector, Auth (magic link + Google), Storage (private `cvs` bucket),
  RLS on **every** table.
- Background jobs: **pg-boss** in a separate Node worker (`worker/`, `pnpm worker`). Web app only
  enqueues jobs. See "Decisions".
- Tests: Vitest (`src/**/*.test.ts`), Playwright (`tests/e2e`).

## Commands

```bash
pnpm dev            # web app
pnpm worker         # pg-boss worker (connector sync, enrichment, embeddings, matching, retention)
pnpm db:start       # local Supabase (Docker)
pnpm db:reset       # re-apply migrations + supabase/seed.sql
pnpm seed           # load ESCO subset, companies, 50 jobs, 5 demo candidates, compute matches
pnpm typecheck      # next typegen && tsc
pnpm lint
pnpm test           # vitest
pnpm test:e2e       # playwright (builds must exist: pnpm build)
```

In Next 16 `params`/`searchParams`/`cookies()` are async. Use the global `PageProps<"/route">` /
`LayoutProps<…>` helpers (generated by `next typegen`) and `resolveLocale(params)` from
`src/i18n/locale.ts` at the top of every page/layout under `[locale]`.

## Decisions (with rationale)

1. **pg-boss + separate worker** instead of Supabase cron + edge functions: multi-stage pipeline
   needs retries/backoff/singletons/rate-limits; same Node/TS code and libraries as the app
   (pdf/docx parsing, XML, local embeddings); no Deno/wall-clock limits. Cost: one extra EU host
   (Fly.io `ams` / Railway EU). pg-boss uses its own `pgboss` schema in the same database.
2. **Embeddings default: local `Xenova/multilingual-e5-base` (768 dims)** via
   `@huggingface/transformers` in the worker (optional dependency). No personal data leaves our
   infra; free. Column type is `vector(768)` – any other provider must output 768 dims
   (Voyage/OpenAI adapters request/truncate to 768). `fake` provider = deterministic hashing
   embedding for tests/offline. e5 needs prefixes: `query: ` for candidate text, `passage: ` for jobs.
3. **No visa / sponsorship / work-permit features** (product decision, Sept 2026): the product targets the
   Dutch labour market in general. There is no sponsorship knock-out, no IND norms and no permit questions;
   do not reintroduce them. Language requirements remain a normal knock-out.
4. **Seed companies are fictional** (no risk of misrepresenting a real employer).
5. Travel time in the MVP = haversine distance between city coordinates × mode factor
   (`TravelTimeProvider`), a routing API can be plugged in later.
6. Connector credentials: AES-256-GCM with `CONNECTOR_ENCRYPTION_KEY`, stored in
   `connector_secrets` (RLS enabled, **no** policies → service role only). Never sent to client.
7. Explanations (top-3 reasons, gaps) are **template-based i18n keys + params**, not LLM text:
   reproducible and auditable, rendered in NL or EN.
8. Missing data never excludes: knock-outs return `pass | fail | unknown`; a component without
   data is `null` and its weight is redistributed (match flagged `limitedData`).
9. **Adding Dutch job boards**: implement a `Connector` in `src/core/connectors/<name>.ts` (fetch → raw,
   map → `NormalizedJob`, healthcheck), register it in `CONNECTORS` in `index.ts`, add a zod config schema,
   a recorded fixture under `__fixtures__` and a test. Feeds without an SDK can use the generic JSON/XML
   connector + mapping editor. Credentials always go to `connector_secrets` (encrypted).

## Compliance rules (must hold in every change)

- The matching engine input type (`MatchCandidate`) **must never** contain name, age/birth date,
  gender, photo, nationality or address. `sanitizeCandidate()` uses an allow-list; the test
  `protected-attributes.test.ts` must stay green.
- CV text is passed through `redactPii()` before it is sent to the ParserProvider or embedded.
- Every match computation writes an `audit_log` row (`action = 'match.compute'`, input hash,
  `model_version_id`). Every admin mutation writes an `audit_log` row.
- Matching model versions are immutable; edits create a new version.
- No automated rejections: knocked-out jobs are hidden by default but the user can "show anyway".
- Registration requires explicit consent (stored in `consents`); employer sharing is a separate
  consent (not used in phase 1).
- Retention: inactive accounts (default 12 months) get a warning mail, then are deleted by the
  `retention` worker job.
- We never ask photo, birth date, gender or nationality anywhere in the UI.

## Conventions

- Server-only modules start with `import "server-only"`.
- Validation with zod (v4) at every boundary (forms, connector raw data, LLM output).
- Admin checks: `requireAdmin()` in `src/server/auth.ts` – call in admin layout AND in each admin
  server action / route handler (layouts alone are not a security boundary).
- UI copy only via next-intl; no hard-coded user-facing strings in components.
- Commits: small, conventional-ish (`feat(matching): …`, `chore: …`), tests green before commit.

## Environment notes (cloud dev container)

- Outbound network is restricted: ESCO API, job-board APIs, HuggingFace and the shadcn registry
  are not reachable. Connectors are tested against recorded fixtures in
  `src/core/connectors/__fixtures__`.
- Docker daemon may need starting: `nohup dockerd >/tmp/dockerd.log 2>&1 &`.
- Playwright uses the pre-installed Chromium (`/opt/pw-browsers/chromium-1194`), see
  `playwright.config.ts`. Never run `playwright install` there.
